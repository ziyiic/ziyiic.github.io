## 为什么重新做一遍

第一版工程和已经调试过的电机参数是参考，不是第二遍实现的替代品。这次的重点是自己理解并重新实现：数据如何流动、模块如何分工，以及中断和任务之间如何安全协作。

这篇文章记录起点和计划，不代表下面的功能已经实现或经过板上验证。

## 本轮边界

目标是按可验证的小功能推进，每完成一段数据链路，再继续下一层控制。电机相关逻辑基于 HAL 或自写适配层实现，不把调用现成 DJI 驱动作为本次成果。

暂时不追求从零重新调出全部参数，也不把外观整理放在正确性之前。

## 先把数据流画清楚

![从上位机命令到电机控制，再回传状态的数据流](data-flow.svg)

图表示计划中的模块关系，不代表最终的中断、DMA 或任务划分。实现各模块前，需要明确它的输入、输出、数据所有权、调用上下文和失败行为。

例如：接收缓冲区还在被 DMA 写入时，任务不能假设其中的数据永远不变；通信超时后，也不能继续把旧命令当作新的控制意图。

## 实施路线

| 阶段 | 要回答的问题 | 主要验证方向 |
| --- | --- | --- |
| 串口 DMA 与协议 | 一帧何时完整？缓冲区由谁读写？ | 分段输入、连续帧、非法帧 |
| 连接检测与安全状态 | 多久算断连？断连后输出是什么？ | 超时、恢复、重复连接 |
| CAN 反馈 | 原始字节如何变成反馈量？ | 标识符、长度、字节序 |
| 电流控制 | 命令如何变成实际输出？ | 限幅、方向、停止路径 |
| 速度 PID | 采样周期和反馈单位是否一致？ | 低速、阶跃、输出饱和 |
| 串级位置环 | 位置误差如何生成速度目标？ | 到位、反向、跨圈边界 |
| 上位机反馈与预设动作 | 状态如何回传？动作如何终止？ | 状态一致性、取消、异常退出 |

## 技术笔记怎么写

下面只演示博客的代码高亮，不是固件实现：

```c
/* 在实际工程中，应先明确这些量的单位和更新周期。 */
float target_speed_rpm;
float measured_speed_rpm;
```

每篇实现记录尽量回答五件事：

1. 观察到了什么问题。
2. 当前设计与接口契约是什么。
3. 为什么采用这种做法。
4. 实际运行了什么验证，结果是什么。
5. 还有哪些条件没有覆盖。

## 验收分三个层次

- **编译与链接**：证明工具链能生成程序，不证明硬件行为正确。
- **调试器观察**：检查缓冲区、状态转移和关键变量，不代替真实通信时序。
- **板上实测**：输入正常、边界和错误场景，记录输出及安全状态。

文章中的“已完成”只用于已有证据的部分。尚未测到的内容，就明确写成计划或待验证。
